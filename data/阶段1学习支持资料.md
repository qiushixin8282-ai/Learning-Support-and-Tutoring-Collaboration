# 学习支持协作实验室资料样例

## 学生任务与资料使用

学生可以查看自己参与项目中的公开资料，以及明确授权给学生角色的学习指南。学生可以创建学习任务、补充实验记录和提交成果草稿，但不能审核成果、发布成果或查看导师专用的评审意见。每个任务应关联责任人、截止日期和来源资料。提交成果时应说明引用了哪些资料、实验记录和代码提交。若学生发现资料缺失，应在任务讨论中提出补充请求，而不应猜测课程规则或实验结论。

学习支持的第一原则是可追溯。任务的状态变化应记录操作人、时间和原因。学生提交的内容在进入正式成果前，需要导师或具有审核权限的人员确认。系统可以提供学习路径建议，但建议仅作为参考，不等于导师结论。对于没有明确资料依据的问题，系统应提示资料中未找到，并建议向导师或助教补充确认。

## 助教协作与版本复核

助教负责协助受理学习任务、整理公开资料、跟进任务状态和提醒截止时间。助教可以编辑自己负责任务的说明、添加材料链接、帮助学生补充实验记录，但不能替代导师对研究结论作出最终审核。资料发布前需要核对版本、适用范围和可见角色。若资料版本不一致，助教应将任务标记为待核对，并通知导师或课程运营人员处理。

成果草稿提交后，助教可以做形式检查，例如来源是否齐全、实验记录是否关联、代码链接是否附带 commit hash。形式检查不能替代学术判断。若发现引用来源缺失、版本错误或实验步骤无法理解，应退回成果并写明返工原因。返工次数由系统依据状态流转自动计算，用于后续评估资料质量和协作效率。

## 导师审核与实验复现

导师负责审核研究成果、判断研究结论是否成立，并决定成果是否可以发布。导师审核时需要填写通过、退回修订或拒绝的决定，并保留审核意见和依据。对于涉及代码的成果，导师应查看关联仓库链接、分支名称和 commit hash；平台不托管代码，也不替代 GitHub 或 Gitee 的版本管理。

实验复现状态由导师或获授权的复现判定人填写，可取值为未测试、可复现、部分可复现和不可复现。每一次复现判定必须保留判定人、日期、运行环境、使用的 commit hash 和证据说明。导师专用审核意见、复现失败细节和未公开研究资料仅可由导师及获得明确授权的负责人访问，不应向学生角色检索或展示。
