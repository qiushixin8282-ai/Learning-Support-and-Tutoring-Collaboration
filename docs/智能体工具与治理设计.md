# 学习支持协作实验室：智能体工具与治理设计

> 版本：v0.1  
> 定位：将资料问答升级为受控智能体。智能体可自主分析、检索、建议和创建草稿，但不得自行触发审核、发布或定稿等正式动作。

## 1. 工具清单

| 工具名 | 用途 | 关键参数 | 返回值 | 是否写入正式记录 |
| --- | --- | --- | --- | --- |
| `search_knowledge` | 按角色检索资料库，返回可引用证据 | `query`、`user_id`、`role`、`top_k` | 切片文本、文件名、切片号、相关度、引用来源 | 否 |
| `generate_summary` | 基于已获授权资料生成摘要 | `source_chunk_ids`、`summary_type` | 摘要、引用列表、未覆盖提示 | 否 |
| `suggest_learning_path` | 结合任务与资料给出学习步骤建议 | `user_id`、`task_id`、`goal` | 学习路径、推荐资料、风险提示、来源 | 否 |
| `check_task_risks` | 检查任务临期、缺少实验记录或代码链接等风险 | `task_id`、`user_id` | 风险级别、原因、建议、依据字段 | 否 |
| `validate_submission_requirements` | 校验成果提交所需关联是否齐全 | `task_id`、`experiment_record_ids`、`code_links`、`result_summary` | `valid`、缺失项、错误码、中文错误信息 | 否 |
| `create_submission_draft` | 创建成果提交草稿，供用户修改确认 | `task_id`、`validation_token`、`title`、`summary`、`source_links` | 草稿 ID、草稿内容、待补充项 | 仅写草稿，不写正式成果 |
| `create_task_draft` | 根据用户明确意图生成新任务草稿 | `title`、`description`、`assignee_ids`、`due_at` | 草稿 ID、建议字段、风险提示 | 仅写草稿，不创建正式任务 |
| `prepare_review_package` | 汇总成果、来源、实验记录和代码提交，供审核人查看 | `submission_draft_id` | 审核材料包、追溯链完整性、缺失项 | 否 |
| `request_human_review` | 生成待人工提交审核的操作卡片 | `submission_draft_id` | 人工确认动作令牌、校验结果 | 否，不能代替人工提交 |
| `answer_with_sources` | 将已检索证据组织为问答答案 | `question`、`evidence_chunk_ids` | 答案、引用来源、置信说明 | 否 |

## 2. 调用顺序与状态约束

### 2.1 资料问答

```text
用户提问
  → 权限过滤检索
  → 基于证据回答、摘要或建议
  → 写入审计日志
```

### 2.2 成果提交草稿

```text
用户提出成果提交意图
  → validate_submission_requirements
  → 校验通过后生成一次性 validation_token
  → create_submission_draft
  → 用户人工确认并修改
  → 人工点击“提交审核”
  → 后端正式提交审核
```

约束如下：

1. 创建成果提交草稿前，必须完成 `validate_submission_requirements`。
2. 校验至少覆盖来源任务、成果说明、关联资料或实验记录，以及任务要求的代码仓链接和 commit hash。
3. `create_submission_draft` 必须携带未过期、且绑定当前用户和任务的 `validation_token`；否则返回 `SUBMISSION_VALIDATION_REQUIRED` 及中文错误信息。
4. 提交审核、审核通过或驳回、标记定稿、发布成果只能由人工在页面上触发。
5. 智能体只可生成建议、草稿和人工待办，不能调用正式状态流转接口。

## 3. 系统提示词与代码层双重约束

### 3.1 系统提示词

建议作为数据库中的可版本化模板：

> 你是学习支持协作实验室的受控智能体。你只能基于已授权的工具返回内容作答，所有结论必须附来源。你可以检索、总结、提出建议和创建草稿，但不得提交审核、发布、定稿或绕过校验创建草稿。工具返回校验失败时，必须如实说明中文错误信息并引导用户补全材料。

### 3.2 代码层强制规则

- 工具注册表按“只读、草稿写入、人工正式写入”分级；智能体不注册正式提交类工具。
- 每个工具根据 JWT 用户、角色、资源归属及“看/改/审/发布”权限复核。
- 向量检索前执行角色可见性过滤，禁止先检索后过滤。
- 草稿工具必须验证前置校验令牌的用户、任务、校验结果和有效期。
- 正式状态流转仅接受人工页面请求，并同时校验 JWT、CSRF、权限和当前状态。
- 模型输出不能直接作为数据库操作执行，所有参数均需通过服务端类型、权限和业务规则校验。

## 4. 审计与来源标注

每次工具调用写入审计日志，最少包含：

```json
{
  "timestamp": "2026-10-30T10:00:00+08:00",
  "trace_id": "一次对话链路ID",
  "user_id": "用户ID",
  "role": "学生",
  "tool_name": "search_knowledge",
  "request_summary": "脱敏后的参数摘要",
  "result_status": "success",
  "source_chunk_ids": ["doc-12#3", "doc-12#4"],
  "model_name": "模型名",
  "risk_flags": []
}
```

所有 AI 面向用户的输出末尾均标注“引用来源：文件名 + 切片序号”。资料不足时固定回答“资料中未找到”，并记录未命中事件。越权检索、校验绕过尝试、无来源结论将自动形成风险标记，供管理员在审计日志页处理。

## 5. 推荐实施顺序

1. 实现只读检索、来源标注和全链路审计。
2. 实现任务与成果草稿工具及前置校验令牌。
3. 接入人工审核页面、正式状态流转和后台风险处理。
