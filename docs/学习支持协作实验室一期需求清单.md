# 学习支持协作实验室 一期需求清单

## 项目目标

为单个实验室的学生与研究人员提供研究学习任务协作平台，统一管理任务、资料、实验记录、讨论和成果追溯，提升研究协作效率、成果产出与实验复现成功率。

一期定位为 1 至 2 个月内完成的受控试点，而非全校级平台。

## 目标用户与角色

- 学生：提交学习或研究任务，阅读资料，参与讨论，提交实验记录与成果。
- 助教：受理问题，分类任务，维护学习材料。
- 导师：指导研究任务，审核关键输出。
- 课题组负责人：查看项目进展、资源与协作指标，决定优先级。
- 教育数据专员：管理数据可见范围、留存与审计。
- 平台管理员：管理账户、角色、系统配置和异常处置。

## 核心业务流程

`注册登录 → 创建或加入研究任务 → 上传或关联资料 → 协作讨论 → 提交实验记录或成果 → 导师审核 → 归档与复盘`

固定任务状态机：`新建 → 已分派 → 进行中 → 待审核 → 需修订 → 已完成 → 已归档`。

每次状态变化必须记录操作人、时间、原因和关联版本。

## 一期功能范围

- 公开注册、邮箱验证、登录与找回密码。
- 基于角色的权限控制。
- 研究任务、子任务、截止日期、责任人和状态管理。
- 文档、数据说明、代码链接、实验记录与成果附件管理。
- 文档版本与审核意见。
- 任务评论与协作讨论。
- AI 辅助：任务摘要、资料检索、学习路径建议、风险提醒。
- 项目看板：任务进度、处理时长、返工次数、实验复现状态。

## 数据与安全边界

系统会处理姓名、邮箱、学习记录及研究协作资料，因此一期必须具备：

- 密码安全存储、邮箱验证与会话管理。
- RBAC 角色权限和课题或项目级数据隔离。
- 私有资料默认仅项目成员可见。
- 上传文件类型、大小与访问权限限制。
- 操作审计日志与数据导出记录。
- 数据最小化、可配置留存期限和删除申请流程。
- AI 不自动发布结论、不自动修改实验记录或研究结果；所有建议需由人确认。

## 推荐架构

- 前端：React 或 Next.js，用于任务看板、资料库、实验记录和管理后台。
- 后端：Python FastAPI 或 Node.js NestJS，提供 REST API。
- 数据库：PostgreSQL，存储用户、角色、任务、评论、审核和审计日志。
- 文件存储：对象存储，保存附件、实验记录和版本化资料。
- 搜索与 AI：向量检索库和大模型服务，用于资料检索、摘要和风险提示。
- 身份认证：邮箱注册登录，后续预留学校统一认证接口。
- 部署：Docker 与云端托管，具备自动备份、日志和基础监控。

## 一期验收标准

- 六类角色可注册、登录，并只能访问其被授权的内容。
- 可创建、分派、讨论、审核、修订和归档研究任务。
- 每个任务可关联文档、代码链接或实验记录，并保留版本。
- AI 可基于授权资料生成摘要、检索结果和风险提醒。
- AI 输出必须有人工确认后采用的控制。
- 管理员可查看任务流转和审计记录。
- 使用一组脱敏试点项目完成端到端演练，并产出试点评估报告。

## 一期不做事项

- 不对接学校正式成绩、学籍或财务系统。
- 不自动评价学生能力或自动决定研究结论。
- 不支持跨校多租户运营。
- 不将真实敏感研究数据直接发送给未审查的第三方 AI 服务。
