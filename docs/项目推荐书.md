# 学习支持与辅导协作项目推荐书

## 推荐结论

建议优先立项 **学习支持请求受控协作与交接原型**。项目以助教、课程运营、课程讲师和学习服务主任之间的支持请求协作为对象，先解决请求分散、规则版本不一致、责任人不清和人工复核无法追溯的问题。

推荐该项目的原因是它能够在小范围内独立验证价值：不需要接入成绩、课程或支付等高风险生产系统，也不以自动生成学习结论替代讲师判断。它可通过脱敏请求样本、受控规则和具名处理责任人完成端到端试点。

## 候选方向比较

| 候选项目 | 解决的问题 | 实施难度 | 风险 | 一期建议 |
| --- | --- | --- | --- | --- |
| 学习支持请求受控协作 | 分拣、规则核对、交接与审计 | 中 | 可通过人工复核控制 | **优先推荐** |
| 学习预警与主动干预 | 识别可能掉队的学习者 | 高 | 涉及模型偏差、解释与个人数据 | 暂缓，先建立数据治理基础 |
| 智能答疑助手 | 提升常规问题响应效率 | 中高 | 容易出现错误答复与越权承诺 | 作为二期能力，依赖一期规则与知识库 |

## 一期最小试点

试点范围为一个课程、一个服务地区和一批脱敏请求样本。统一入口将请求转换为包含匿名编号、主题、区域、规则版本、授权状态、提出角色和具名责任人的任务。系统执行三项硬控制：

1. 未确认授权，不自动分派；
2. 服务规则版本不匹配，不自动分派；
3. 未指定具名责任人，不自动分派。

任一控制未通过时，任务进入学习服务主任的人工复核队列，并记录原因、下一责任人与审计事件。

## 预期交付

| 类别 | 交付物 |
| --- | --- |
| 业务 | 机会清单、角色地图、现状与目标流程图、指标口径 |
| 需求 | 需求规格、验收条件、权限与异常处理矩阵 |
| 技术 | 任务数据契约、受控分派原型、审计事件记录、单元测试 |
| 验证 | 脱敏评估集、试点计划、复盘记录、扩大或停止建议 |

## 验收指标

试点前先按同一口径建立基线；试点中至少记录首次响应时长、平均处理时长、返工次数、规则版本正确率和人工复核分钟数。关键验收条件如下：

- 控制项完整的请求可正确进入指定责任人队列；
- 任意控制项缺失的请求必须进入人工复核，且原因可见；
- 关键场景的规则版本正确率为 100%；
- 试点结果能与基线或对照样本比较，并能说明异常原因。

## 决策与停止条件

学习服务主任负责业务范围与继续决策，教育数据专员负责数据与留存审查，平台工程师负责技术可行性和回滚准备。若无法获得样本脱敏授权、规则版本无法维护、责任人无法落实，或试点出现重大隐私与错误分流风险，应停止扩大范围，回到调研和需求定义阶段补齐证据。
