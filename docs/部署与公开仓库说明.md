# 部署与公开仓库说明

## 公开前安全检查

本仓库在公开前应扫描工作区与全部 Git 历史，确认不存在真实 API Key、密码、访问令牌、真实实验数据、个人手机号、学号或未授权课程资料。若发现历史密钥，必须先在供应商侧作废，再使用历史重写工具清理并强制推送。

本次整理时已完成常见密钥模式与个人信息关键词的工作区、历史扫描；命中项仅为安全文档和测试用例中的通用文字，没有发现真实凭证或个人数据。`data/` 中内容为自编匿名示例。

## 创建和公开 GitHub 仓库

可在 GitHub 网页新建仓库，再在本地执行：

```bash
git init
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git add .
git commit -m "feat: initialize lab support project"
git push -u origin main
```

若已安装并登录 GitHub CLI，可创建公开仓库：

```bash
gh repo create <用户名>/<仓库名> --public --source=. --remote=origin --push
```

将既有私有仓库改为公开：

```bash
gh repo edit <用户名>/<仓库名> --visibility public
```

## 提交信息规范

- `feat:` 新功能或新增可运行模块。
- `fix:` 缺陷修复或安全修复。
- `docs:` 文档、架构和交付说明更新。
- `test:` 测试、评测用例或验证脚本更新。
- `chore:` 构建、依赖或工程结构维护。

## 推送后的未登录检查

1. 使用浏览器无痕窗口打开仓库链接。
2. 确认 README 首页正常渲染、项目定位和运行说明清晰。
3. 检查根目录不存在 `.env`、数据库、FAISS 索引、JSONL 审计日志和虚拟环境。
4. 检查 `data/` 只有声明过的匿名示例资料。
5. 打开提交历史，确认没有真实凭证或隐私数据。
