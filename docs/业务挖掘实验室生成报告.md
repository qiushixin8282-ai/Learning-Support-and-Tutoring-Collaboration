# 学习支持与辅导协作业务挖掘报告

生成方式：本地学习支持协作实验室  
报告状态：训练样例 已完成六类角色事实采集

## 已采集证据

- E-01 顾明岚 学习服务主任：支持响应应可控、可衡量；业务负责人依据指标与风险决定是否继续试点。
- E-02 林亦舟 助教：请求来源分散，助教需要人工判断能否直接解答；复杂问题需要转派讲师。
- E-03 唐映秋 课程运营员：发布前需要核对辅导材料和规则版本；版本不一致会造成返工。
- E-04 秦芮 学习平台工程师：系统可承接任务编号、状态和审计事件；生产接入前需要确认权限与回滚。
- E-05 傅景 教育数据专员：应最小化收集字段，确认授权、可见范围和留存要求后再使用样本。
- E-06 叶书 课程讲师：涉及课程判断的请求必须由讲师确认；需要保留答复依据和反馈。

## 业务机会

将分散的学习支持请求转为可追溯任务，在分派前核验授权、规则版本与具名责任人。项目优先解决重复分拣、错误版本、责任不清和跨角色交接返工。

## 指标基线与价值假设

试点前按同一口径记录处理时长、返工次数、版本正确率、采用率和人工复核分钟数。受控任务分派预计能减少因信息缺失和规则版本不一致造成的返工；具体改善幅度须由脱敏样本和对照基线验证。

## 项目章程与决策链

学习服务主任负责范围与继续决策；教育数据专员审查数据、权限和留存；平台工程师确认技术可行性与回滚；课程讲师负责学习内容判断；助教和课程运营员负责请求受理、材料核对与协作交接。

## 待验证项

1. 取得同一课程、同一地区的脱敏请求样本与系统日志，建立基线。
2. 核对服务规则版本、适用范围和例外转人工路径。
3. 明确试点课程、地区、样本量、对照方法和停止条件。
4. 在上线前完成数据访问、权限矩阵和审计留存的具名确认。
