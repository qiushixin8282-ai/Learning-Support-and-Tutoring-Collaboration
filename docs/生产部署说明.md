# 生产部署说明

## 定位与边界

本说明用于将当前教学 MVP 部署为可访问的后端服务。当前 [演示站点](https://learning-support-collab-lab.starryprawn17.chatgpt.site) 为账号受限的静态演示，**不是**该后端的公网生产地址。正式对外前仍需由学校确认域名、HTTPS 证书、数据保留期限和账号开通范围。

## 前置条件

| 项目 | 要求 |
|---|---|
| 运行环境 | Docker Engine 与 Docker Compose v2 |
| 域名 | 已解析到部署主机；生产入口应由反向代理提供 HTTPS |
| 密钥 | `JWT_SECRET` 至少 32 位随机值，不提交至 Git |
| 主机白名单 | `TRUSTED_HOSTS` 填实际域名，逗号分隔 |
| 数据 | Docker 卷 `lab-instance`、`lab-uploads` 已纳入备份策略 |

## 部署步骤

1. 从 `.env.example` 复制为部署主机私有的 `.env`，填写 LLM 凭据、强随机 `JWT_SECRET` 与实际 `TRUSTED_HOSTS`。
2. 设置 `APP_ENV=production`，运行 `sh scripts/deploy.sh`。
3. 通过反向代理将 HTTPS 请求转发到 `127.0.0.1:8000`，不直接向公网暴露容器端口。
4. 访问 `GET /health`，预期 HTTP 200；用管理员、助教、学生账户完成一次登录和权限回归。

## 内置保障与验收

| 控制项 | 实现 | 验收方式 |
|---|---|---|
| 启动拦截 | 生产环境拒绝弱 JWT 密钥与空 Host 白名单 | 删除任一配置后容器启动失败且给出明确错误 |
| Cookie | 生产环境登录 Cookie 自动启用 `Secure` | HTTPS 登录后检查响应 `Set-Cookie` 包含 `Secure` |
| Host 校验 | `TrustedHostMiddleware` 按白名单拒绝伪造 Host | 非白名单 Host 返回 400 |
| 轻量限流 | 登录与后台问答每客户端每路径默认 30 次/分钟 | 第 31 次请求返回 429 与 `RATE_LIMITED` |
| 健康检查 | Docker 每 30 秒请求 `/health` | `docker compose ps` 显示 healthy |

## 回滚与恢复

保留上一版本镜像标签和部署前的数据库备份；异常时执行 `docker compose down`，以已验证镜像重新启动，再从备份恢复 `lab-instance` 卷。恢复后必须复测 `/health`、登录、任务提交、助教初审和导师终审五项路径，并记录到运行手册。
