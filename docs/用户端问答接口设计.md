# 学习支持协作实验室用户端问答接口设计

## 设计目标

为学生、助教和导师提供带模拟角色权限控制的资料问答入口。回答必须经过角色过滤后的混合检索，展示来源切片，并将会话、消息和审计记录持久化。

阶段 1 没有 SQLite 表，本阶段新增轻量 SQLite 会话表，同时保留阶段 1 JSONL 审计字段和权限过滤逻辑。

## POST /chat

提交问题并以 SSE 流式返回回答。

请求体：

```json
{
  "session_id": "lab-demo-001",
  "question": "学生可以审核成果吗？",
  "role": "学生"
}
```

| 字段 | 必填 | 说明 |
| --- | ---: | --- |
| `session_id` | 是 | 客户端生成或沿用的会话 ID，最大 64 字符 |
| `question` | 是 | 去除空白后不能为空，最大 2000 字符 |
| `role` | 是 | 仅允许：学生、助教、导师 |

参数错误返回：

```json
{
  "code": "INVALID_ROLE",
  "message": "角色仅支持：学生、助教、导师"
}
```

| HTTP 状态 | 错误码 | 中文信息 |
| ---: | --- | --- |
| 400 | `INVALID_REQUEST` | 请求参数不完整或格式错误 |
| 400 | `EMPTY_QUESTION` | 问题不能为空 |
| 400 | `INVALID_ROLE` | 角色仅支持：学生、助教、导师 |
| 404 | `NO_VISIBLE_MATERIAL` | 当前角色无可访问资料 |
| 429 | `LLM_RATE_LIMITED` | 模型服务繁忙，请稍后重试 |
| 500 | `LLM_UNAVAILABLE` | 模型服务暂时不可用 |
| 500 | `INTERNAL_ERROR` | 系统内部错误，请联系管理员 |

成功响应头：

```text
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
```

SSE 事件顺序：

```text
event: status
data: {"status":"retrieving","message":"正在检索资料…"}

event: sources
data: {"sources":[{"file_name":"阶段1学习支持资料.md","chunk_no":1}]}

event: delta
data: {"text":"学生"}

event: done
data: {"session_id":"lab-demo-001","message_id":18,"audit_id":"2026-...-uuid"}
```

没有命中资料时，不调用 LLM：

```text
event: status
data: {"status":"not_found","message":"资料中未找到"}

event: done
data: {"session_id":"lab-demo-001","message_id":18}
```

流式过程发生错误：

```text
event: error
data: {"code":"LLM_UNAVAILABLE","message":"模型服务暂时不可用"}
```

## GET /sessions/{session_id}/messages

用于页面刷新后恢复历史会话。成功返回：

```json
{
  "code": "OK",
  "message": "查询成功",
  "data": {
    "session_id": "lab-demo-001",
    "messages": [
      {
        "id": 17,
        "role": "user",
        "content": "学生可以审核成果吗？",
        "simulated_role": "学生",
        "sources": [],
        "created_at": "2026-10-30T10:00:00Z"
      },
      {
        "id": 18,
        "role": "assistant",
        "content": "学生不能审核成果。",
        "simulated_role": "学生",
        "sources": [{"file_name":"阶段1学习支持资料.md","chunk_no":1}],
        "created_at": "2026-10-30T10:00:03Z"
      }
    ]
  }
}
```

## GET /health

    "database": "ready",

## SQLite 表结构

```text
chat_sessions
├── id                  TEXT PRIMARY KEY
├── simulated_role      TEXT NOT NULL
├── created_at          DATETIME NOT NULL
└── updated_at          DATETIME NOT NULL

chat_messages
├── id                  INTEGER PRIMARY KEY AUTOINCREMENT
├── session_id          TEXT NOT NULL → chat_sessions.id
├── sender              TEXT NOT NULL       # user / assistant
├── simulated_role      TEXT NOT NULL
├── content             TEXT NOT NULL
├── sources_json        TEXT NOT NULL       # [{file_name, chunk_no}]
├── created_at          DATETIME NOT NULL
└── FOREIGN KEY(session_id) REFERENCES chat_sessions(id)
```

每次 `/chat` 请求依次执行：校验请求、保存用户消息、读取最近 12 条消息作为 6 轮上下文、按角色过滤资料、混合检索、流式调用模型、保存助手消息和来源、写入 JSONL 审计日志。

## 前端交互

页面提供角色切换、对话记录、输入框与发送按钮。前端读取 SSE：

- 收到 `status: retrieving` 时显示“正在检索资料…”。
- 收到 `delta` 时逐字追加，实现打字机效果。
- 收到 `sources` 或 `done` 时展示来源文件和切片编号。
- 收到 `error` 时显示中文错误信息。
- 角色切换生成新 `session_id`，避免不同权限角色共享上下文。
- 浏览器保存当前会话 ID，刷新后通过会话查询接口恢复历史。
