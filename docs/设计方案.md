# 学习支持与辅导协作设计方案

## 目标

在不替代教育判断的前提下，将学习支持请求转换为可追溯的服务任务，缩短分拣和交接时间，并让规则版本、授权状态与处理责任在分派前可核验。

## 一期范围

- 统一请求入口：记录匿名请求编号、主题、区域和提出角色。
- 规则控制：核验服务规则版本与授权状态。
- 人工协作：将通过核验的任务分派给具名负责人；未通过的任务进入学习服务主任复核队列。
- 审计与复盘：记录决定、原因、下一责任人与事件时间线。

## 不在一期范围

- 自动修改成绩、课程、学习档案或生产业务系统。
- 用模型替代讲师对学习内容、申诉或特殊支持的最终判断。
- 处理未经授权的个人信息。

## 角色与责任

| 角色 | 责任 |
| --- | --- |
| 学习服务主任 | 批准试点边界，复核异常，决定继续或停止 |
| 助教 | 提出或补充学习支持请求 |
| 课程运营员 | 核对流程、材料和交接状态 |
| 课程讲师 | 处理具名任务并给出专业答复 |
| 教育数据专员 | 审查字段、权限、留存与审计要求 |
| 平台工程师 | 实现接口、日志、权限和版本发布 |

## 技术实现

原型采用 Python 领域模型和可测试规则函数。`SupportRequest` 保存最小业务字段；`evaluate_request` 以授权、规则版本和具名责任人为硬控制；任何缺失均返回 `needs_human_review`，不会自动继续。后续可在保留同一数据契约的基础上接入身份认证、任务队列和审计存储。

## 验收与风险控制

一期验收：合成样例中控制项齐全的请求可进入指定责任人队列；任一控制项缺失时必须转人工复核并给出原因。上线前需完成真实样本脱敏、权限审批、业务验收和回滚演练。
