# FDE 全流程训练交付包

> 状态说明：以下为合成训练场景的交付草案。`E-*` 为待采集证据，`H-*` 为待验证假设，不代表真实客户授权、真实收益或已上线系统。

## 1. 业务挖掘

**机会清单。** 助教、课程运营和讲师间的支持请求存在版本与责任交接断点；若维持现状，可能造成重复核对、延迟回复和人工复核成本上升（E-01 至 E-03 待访谈）。

**指标基线与价值假设。** 基线应按周抽取样本，记录首次响应时长、平均处理时长、返工次数、规则版本正确率、人工复核分钟数及采用率。H-01：通过前置核对可降低因信息缺失造成的返工；未采集样本前不得填写具体节约率。

**项目章程。** 业务负责人：学习服务主任；范围批准：学习服务主任；数据访问批准：教育数据专员；技术实施：学习平台工程师；继续或停止决定：业务负责人基于试点指标作出。停止条件：授权不清、版本无法核验或处理责任无法落实。

## 2. 现场调研

访谈对象为学习服务主任、助教、课程运营员、平台工程师、教育数据专员、课程讲师。访谈应逐项记录原话、时间、样例编号与核验状态（E-01 角色陈述、E-02 脱敏请求样本、E-03 现行规则、E-04 系统日志）。

现状流程：请求进入 → 核对区域/模块 → 核对规则版本与交接 → 确认授权 → 具名责任人处理 → 反馈与复盘。异常：资料缺失、授权不明、版本不一致、责任人缺失；均转人工并保留原因。

## 3. 需求定义

| ID | 需求 | 验收条件 | 边界 |
| --- | --- | --- | --- |
| RQ-01 | 请求可追溯 | 每项有匿名 ID、来源角色和审计事件 | 不保存真实学生身份信息 |
| RQ-02 | 规则受控 | 版本不匹配必须阻止自动分流 | 规则内容仍由人工维护 |
| RQ-03 | 人工交接 | 缺授权或责任人时指定复核人 | 不自动批准或发送外部通知 |

优先级：RQ-02、RQ-03 为 P0，RQ-01 为 P1。确认人、日期和真实证据编号待现场调研后补齐。

## 4. 方案设计

最小试点：一个课程、一个地区、少量脱敏请求样本；比较“人工表格核对”与“受控任务分流”。数据最小化字段见 [API](api.md)。权限矩阵：助教可提出请求；课程运营可补充材料；讲师处理；数据专员审查；主任决定继续/停止。

风险：错误规则版本、越权访问、自动化越界、指标偏差。控制：版本硬校验、最小权限、人工复核回退、样本口径冻结。

## 5. 构建集成

已交付 Python 原型：`SupportRequest`、`evaluate_request`、匿名样例、CLI 和审计事件。数据契约为 JSON 样例；真实接口、认证、数据库和消息通知不在范围内。

## 6. 测试评估

测试覆盖：控制条件完整时进入责任人队列；授权、版本、责任人任一缺失时进入人工复核。评估集仅使用 `data/sample_requests.json` 合成数据。真实模型验证和业务验收尚未发生。

## 7. 客户试点

试点前需业务、数据与技术三方书面确认：样本脱敏、人员名单、指标口径、退出机制。比较同口径的试点前后或受控对照组；若错误分流、隐私风险或关键指标恶化，立即停止扩大范围。

## 8. 上线交接

上线前检查：需求验收、权限审查、审计留存、回滚步骤、运行负责人和支持联系人均需具名。当前原型没有生产部署配置；`scripts/deploy.sh` 只提示必须先获得审批。

## 9. 运营迭代

30 天核对质量与异常；60 天复盘返工和人工复核成本；90 天决定扩大、修正或停止。事件记录应包含：版本、影响范围、临时控制、责任人、复盘结论。每季度重新进入业务挖掘，更新证据与优先级。
